# Kainy's Nivalis Nights Trainer · v0.5-Dev-UI-Audit2

当前版本在首页提供“手动注入”“探测玩家数据”和“无偿捐赠作者”，基础选项提供“修改余额为 [数值] [确定]”。金额按用户金币显示值输入，内部按 1 金币 = 100 个游戏整数单位传输；已验证的安全范围为 0.01–21474836.46。

探测和余额设置通过 PlayerHook 的本地 IPC 排队，在游戏主线程执行。命令接收、目标解析、写入和结果事件写入游戏目录的 BepInEx 日志；注入器窗口日志只记录注入生命周期。

双击 NivalisNightsTrainer.exe，点击“手动注入”自动查找运行中的 Nivalis Nights 进程；无需选择游戏路径。保留整个发布目录；GUI 自带私有 .NET 运行时。

## 使用

- 仅保留“手动注入”（动态加载）：游戏出现主窗口后，执行一次性窗口线程加载，初始化 CoreCLR/BepInEx 和四个钩子；卸除临时加载回调。仅当前游戏进程有效。
- 静态注入按钮、安装 API 和发布包启动代理已移除。不分发或部署 winhttp.dll、doorstop_config.ini、.doorstop_version。旧安装需单独清理；不要使用旧版修改器重新安装启动代理。
- 已加载 CoreCLR 的进程拒绝重复初始化。更新已加载的钩子需要保存并重启游戏；失败或超时不自动重试，也不强制结束游戏。
- 默认不观察、无快照或游戏内日志轮询定时器。保留用户配置；明确启用的允许列表和诊断仍按配置执行。
- 校验游戏双哈希、发布包 SHA256；拒绝覆盖不同运行时及重复插件，更新自有插件先备份，失败回滚。

## 日志和功能审计

- 注入器日志：发布目录 logs/injector-{PID}-{启动时间ticks}.jsonl。Trainer 仅显示注入器日志，不含实时钩子日志页。
- 钩子日志：游戏目录 BepInEx/logs/NightsHack/hooks-{PID}-{启动时间ticks}.jsonl。按进程会话匹配，不把旧进程日志当成本次结果。
- 记录时间、级别、事件码、请求 ID、组件、目标、操作、结果；注入成功需要实际确认四条属于本次请求的 HOOK_READY。
- 钩子事件发生时立即写入；Trainer 不再轮询或显示钩子日志，保留既有加载器日志输出和钩子审计文件。
- 未来功能必须经 ObservationPlugin.ExecuteCommand / HookAudit.Execute：请求接收 → 目标验证 → 操作开始 → 明确结果/失败。包括功能名、钩子、目标签名和操作描述；功能调用方必须提供有意义的参数/实际结果摘要。
- 日志不可用时拒绝开始操作；操作开始后异常标为 SideEffectsUnknown，不声称回滚成功、不自动重试。
- 当前已实现玩家实例探测和余额设置；加物品等其他功能仍需补实例/状态验证及游戏内结果验证，不会自动审计任意绕过包装的代码。
